# Domain documentation

This is a single-context repository. Read the root `CONTEXT.md` before using domain terminology, and relevant decisions under `docs/adr/` before changing behavior. Use glossary terms in tickets, implementation, and reports.

The approved product design lives in `docs/design.md`; GitHub issues contain implementation acceptance criteria. If a proposed change conflicts with an ADR, surface the conflict rather than silently overriding it. Update the glossary when a term is resolved and record consequential tradeoffs in concise ADRs.
